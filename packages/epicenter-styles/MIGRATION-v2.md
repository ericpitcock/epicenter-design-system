# Migrating to v2

v2 renames CSS custom properties to a single naming contract and wraps the published
stylesheet in cascade layers. There are **no back-compat aliases** — old names stop
working. Everything below can be applied mechanically.

## 1. Run the codemod

```bash
node node_modules/@ericpitcock/epicenter-styles/scripts/codemod-v2.mjs --dry-run src/
node node_modules/@ericpitcock/epicenter-styles/scripts/codemod-v2.mjs src/
```

It rewrites every renamed property across `.css`, `.scss`, `.vue`, `.ts(x)`, `.js(x)`
and `.html` — declarations, `var()` references, and inline style objects. It is the
same tool the design system used on itself.

## 2. Delete your `!important`

The stylesheet now ships in cascade layers:

```
epicenter.reset, epicenter.tokens, epicenter.base, epicenter.components, epicenter.utilities
```

**Any CSS you write outside a layer beats all of it, regardless of specificity.** If
you were out-specifying the library or reaching for `!important` to override a
component, you can stop.

Target the component's own element. Components declare their defaults on their root
class, so a value inherited from an ancestor loses to them:

```css
/* before */
.my-app .ep-menu__item .ep-button--menu-item { background: rebeccapurple !important; }

/* after */
.my-app .ep-button--menu-item { --ep-button-bg-color: rebeccapurple; }
```

If you deliberately layer your own CSS, put your layer after `epicenter.utilities`.

## 3. Things that now work which did not before

These were broken, not merely renamed — check whether you have workarounds for them:

- **`--primary-color-*` ships.** It was generated by a SCSS mixin the consumer had to
  invoke, so the package was unstyled standalone. Rebrand by overriding
  `--primary-color-base`, or keep calling `generate-color-variants()`.
- **Form error states render.** `--error-color*` was referenced but never declared.
- **Selected table rows have text colour.** They referenced `--white`, which did not exist.
- **Table row hover/stripe work without a theme class.** They were declared only under
  `.dark-theme`/`.light-theme`; they are `light-dark()` pairs now.
- **`::selection` is styled.** `--text-selection-*` was referenced but never declared.
- **Chart colours work without a theme class.**
- **Disabled toggles style correctly.** Two selectors were missing their `ep-` prefix.
- **Breadcrumb CSS applies.** The stylesheet targeted `.ep-breadcrumb`; the component
  renders `.ep-breadcrumbs`.
- **`--ep-input-focus-border-color`, `--ep-textarea-focus-border-color` and
  `--ep-tabs-focus-outline-color` do something.** All three were declared but never consumed.

## 6. Removed

| Removed | Instead |
|---|---|
| `--ep-button-<variant>-*` (all 60: primary, secondary, success, warning, danger, outline, ghost) | Set the public `--ep-button-*` properties directly. Hover and active now derive from `--ep-button-bg-color`, so overriding the base colour is enough. |
| `--ep-case-study-carousel-*` | `--ep-carousel-*` — the alias layer existed only because the real properties were not overridable. |
| `--ep-carousel-peek-width` | Nothing consumed it. |
| `--image-*` (EpAppImage) | `--ep-app-image-*` |
| `--logo-*` (EpicenterLogo) | `--ep-logo-*`, declared on a new `.ep-logo` root class. Note `--logo-hightlight-color` was misspelled; it is `--ep-logo-highlight-fill-color`. |
| `--ep-dropdown-padding-top` | `--ep-dropdown-offset` |
| `--ep-tooltip-offset-x` / `-y` as fallback-only | Now really declared, so they are discoverable and overridable. |

## 7. Behaviour changes to check

- **`EpOverlay` is centred by default.** It was pinned to `top: 3rem; right: 3rem` inside
  a scoped block, so every modal in every app sat in the top-right corner with no way
  to move it. If you relied on that position:
  ```css
  .ep-dialog { --ep-overlay-top: 3rem; --ep-overlay-right: 3rem;
               --ep-overlay-left: auto; --ep-overlay-translate-x: 0; --ep-overlay-translate-y: 0; }
  ```
- **Vue SFCs no longer ship scoped styles.** If you were overriding component internals
  with `:deep()`, those selectors still work but are no longer necessary — the styles
  are global and property-driven now.
- **`EpMultiSearch` props emit custom properties**, not plain inline styles. The
  `borderColor`, `borderStyle` and `borderWidth` props were never consumed and are gone.
- **`prefers-reduced-motion` is honoured globally.** Transitions and animations collapse
  to near-zero for users who ask for it.
